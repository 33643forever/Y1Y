# Y1Y OpenRouter 分支优化需求说明

## 1. 文档信息

- 文档状态：需求基线
- 适用分支：`OpenRoter_build`
- 目标平台：macOS
- 需求范围：浮窗 Markdown 渲染、AI 回复页窗口缩放、结果浮窗置顶固定、OpenRouter 余额展示迁移
- 实现状态：功能已实现并验证

> 本文档记录已确认的产品需求和功能边界。所有需求范围内的功能均已实现并通过测试验收。

## 2. 项目背景

Y1Y 是一款 macOS 全局 AI 文本处理工具。用户可以在其他应用中选中文本，通过全局快捷键唤起浮窗，选择预设提示词或输入自定义指令，并在浮窗内查看 AI 的流式回复。

当前 OpenRouter 分支的浮窗已经能够展示 AI 回复，并提供基础的 Markdown 渲染尝试，但渲染范围和交互规则尚不明确；浮窗尺寸目前主要由程序自动调整，用户不能在 AI 回复页面自由拖拽改变内容窗口大小；OpenRouter 可用余额目前占用了浮窗顶部空间。

本轮优化希望改善 AI 回复的阅读体验，让用户可以在需要时保留结果浮窗并与其他应用并行工作，同时将账户类信息从高频使用的浮窗迁移到设置页。

## 3. 产品目标

本轮需求包含四个目标：

1. 让 AI 回复中的常用 Markdown 内容能够在流式输出过程中直接渲染，提高结构化内容的可读性。
2. 允许用户在 AI 回复页面通过鼠标拖拽调整浮窗尺寸，并在后续使用中复用用户选择的尺寸。
3. 允许用户固定结果浮窗，使其不会因切换到其他应用或点击外部区域而自动消失，并始终显示在其他普通窗口上方。
4. 将 OpenRouter 可用余额从浮窗移至设置页的 API 配置区域，减少浮窗干扰，同时保留余额和连接状态信息。

## 4. 目标用户

目标用户为使用 Y1Y 调用 OpenRouter 模型，并通过 macOS 浮窗快速处理选中文本的用户。

本轮优先服务一般的短文本和常规 AI 回复阅读场景，不针对超长文档阅读或专业 Markdown 编辑场景进行专项设计。

## 5. 核心使用场景

### 5.1 阅读结构化 AI 回复

用户选中文本并调用 Y1Y 后，AI 返回包含标题、列表、强调、引用或代码等 Markdown 内容。浮窗在流式输出期间持续将内容渲染为易读的格式，用户不需要等待整段回复结束。

### 5.2 调整 AI 回复窗口

当默认回复窗口不能舒适地展示内容时，用户可以在 AI 回复页面拖拽窗口边缘或角落改变窗口大小。窗口始终位于当前屏幕可见区域内。

### 5.3 复用窗口尺寸

用户完成一次手动缩放后，应用保存该尺寸。用户后续再次使用浮窗时，AI 回复页面使用已保存的尺寸，减少重复调整。

### 5.4 固定结果浮窗并继续工作

用户获得 AI 回复后，可以点击结果浮窗右上角的固定图标。图标进入点亮状态，结果浮窗保持显示并位于其他普通应用窗口上方。用户可以切换到其他应用继续工作，同时查看、移动或缩放该结果浮窗。

如果已有结果浮窗被固定，用户仍可再次通过全局快捷键发起新的处理任务。新任务使用一个新的浮窗，不替换或关闭已有的固定结果。

### 5.5 查看 OpenRouter 余额

使用 OpenRouter API 的用户打开设置页时，应用自动获取账户当前可用余额，并在 API 配置区域展示余额、刷新时间和连接状态。浮窗中不再出现余额信息。

## 6. 功能范围

### 6.1 Markdown 渲染

#### 功能要求

1. AI 最终回复内容支持常用 Markdown 格式渲染。
2. Markdown 在流式响应过程中实时渲染，不等待回复全部完成。
3. 渲染后的文字允许用户选择。
4. 现有“复制”功能继续复制 AI 回复的原始文本，不因视觉渲染而丢失 Markdown 内容。
5. 流式内容更新时，回复区域继续自动跟随最新内容。
6. 用户主动滚动回复内容时，以用户滚动位置为最高优先级，暂停自动滚动到底部；只有当用户重新滚动到底部后，才恢复对后续流式内容的自动跟随。

#### Markdown 格式范围

第一版支持以下普通、常用的 Markdown 格式：

- 标题
- 粗体和斜体
- 删除线
- 有序列表和无序列表
- 引用
- 分隔线
- 行内代码
- 多行代码块
- Markdown 链接
- 代码块独立复制按钮

以下格式不默认纳入，除非后续明确确认：

- 表格
- 图片
- 数学公式
- HTML 标签
- 脚注
- Mermaid 等扩展语法
- 代码语法高亮

#### 流式渲染边界

- 回复尚未输出完整时，Markdown 标记可能处于暂未闭合状态。
- 实现应保证应用不崩溃、内容不丢失，并能在后续内容补全后更新渲染结果。
- 未闭合的 Markdown 在流式过程中暂时按普通文本展示；标记闭合后，再更新为对应的 Markdown 渲染结果。

### 6.2 AI 回复页面窗口缩放

#### 功能要求

1. 仅 AI 回复页面允许用户通过鼠标拖拽调整浮窗大小。
2. 提示词列表页面不提供用户拖拽缩放能力。
3. 最小尺寸为当前 AI 回复页面的默认尺寸 `380 × 360 pt`。
4. 最大宽度不得超过最小宽度的五倍，最大高度不得超过最小高度的五倍，同时不得超过当前屏幕可用范围。
5. 缩放过程中，窗口和可交互区域不得移出当前屏幕。
6. 屏幕边界限制以浮窗当前所在的屏幕为准，需兼容多显示器场景。
7. 窗口内容区域随尺寸变化自适应布局。
8. 调整窗口大小不得影响回复继续生成、滚动、复制和返回操作。

#### 当前尺寸基线

AI 回复页面的最小尺寸确定为 `380 × 360 pt`。按照五倍规则，理论最大宽度为 `1900 pt`，理论最大高度为 `1800 pt`；实际尺寸仍须受当前屏幕可用区域限制。

#### 屏幕边界规则

- 窗口的上、下、左、右边界均不得超出当前屏幕的可用显示区域。
- 当用户的缩放操作会导致窗口超出屏幕时，应用应限制尺寸或同步修正位置。
- 在尺寸上限和屏幕边界发生冲突时，以“完整保持在屏幕内”为最高优先级。

### 6.3 窗口尺寸记忆

#### 功能要求

1. 用户手动调整 AI 回复窗口后，应用保存调整后的尺寸。
2. 保存的尺寸跨浮窗关闭和再次打开后继续有效。
3. 应用重新启动后仍应保留该尺寸。
4. 恢复尺寸时仍需执行当前屏幕边界检查。
5. 如果显示器配置、分辨率或可用区域变化，已保存尺寸超出当前屏幕能力时，应缩小至当前屏幕允许的尺寸。
6. 提示词列表始终使用现有固定紧凑尺寸，不应用用户保存的 AI 回复窗口尺寸。
7. 用户发起处理并进入 AI 回复页面时，应在结果开始生成前应用已保存尺寸，避免生成过程中发生一次不必要的窗口跳变。
8. 从 AI 回复页面返回提示词列表时，恢复提示词列表的固定紧凑尺寸。

#### 边界

- 本轮不提供“恢复默认窗口大小”入口。

### 6.4 结果浮窗置顶固定

#### 功能要求

1. 固定功能仅作用于展示 AI 结果的浮窗，不作用于提示词列表页面。
2. AI 回复页面最右上角提供一个固定图标。
3. 未固定时，图标显示为默认状态；固定后，图标进入明确的点亮状态。
4. 用户点击未固定图标后，结果浮窗进入固定状态。
5. 固定状态下，结果浮窗不得因为用户点击窗口外部或切换到其他应用而自动关闭。
6. 固定状态下，结果浮窗应保持在其他普通应用窗口上方。
7. 固定状态下，用户可以拖动浮窗改变位置。
8. 固定状态下，用户可以在 AI 回复页面拖拽调整浮窗大小，并继续受最小尺寸、最大尺寸和屏幕边界规则约束。
9. 用户再次点击已点亮的固定图标后，结果浮窗退出固定状态。
10. 固定和取消固定不得中断正在进行的 AI 流式回复，不得清空已经生成的结果。
11. 固定图标应提供可识别的悬停提示和辅助功能名称，且不能遮挡回复内容或其他操作按钮。
12. 无论固定与否，浮窗的完整边界都必须保持在当前屏幕可用区域内。
13. 固定状态只对当前结果浮窗有效；关闭该浮窗后状态重置，不在下次唤起或应用重启后恢复。
14. 已有固定结果浮窗时，再次触发全局快捷键应创建新的浮窗，不得替换或关闭已有固定结果。
15. 多个已固定结果浮窗可以同时存在，每个窗口分别管理自己的固定状态、位置、尺寸和回复内容。
16. 取消固定后窗口继续显示，并在用户下一次点击窗口外部时按照普通浮窗规则关闭。
17. 本轮不新增独立关闭按钮或新的键盘关闭方式，沿用现有关闭交互。
18. 固定窗口的位置不跨浮窗关闭或应用重启保存。
19. 置顶层级只要求高于普通应用窗口，不要求覆盖系统安全提示、系统级窗口或其他更高层级窗口。

#### 交互状态

- 未固定：固定图标处于默认状态，窗口遵循普通结果浮窗的自动关闭规则。
- 固定：固定图标点亮，窗口保持显示并位于其他普通应用窗口上方。
- 取消固定：图标恢复默认状态，窗口继续显示；用户下一次点击窗口外部时，窗口按普通浮窗规则关闭。

#### 位置调整

- 固定结果浮窗允许用户通过拖动窗口背景或指定拖动区域改变窗口位置。
- 移动过程中，浮窗不得被拖出当前屏幕的可用区域。
- 多显示器环境下，窗口可以移动到其他显示器；完成移动后，应以窗口所在显示器的可用区域重新执行边界约束。
- “窗口位置可以改变”已确定，但窗口位置不跨浮窗关闭或应用重启保存。

#### 与现有自动关闭行为的关系

现有实现会监听窗口外部的鼠标点击并关闭浮窗。固定状态下必须绕过该自动关闭逻辑；未固定状态继续沿用现有行为。用户取消固定时不立即关闭窗口，而是从下一次窗口外部点击开始恢复自动关闭。

#### 多窗口规则

- 已有固定结果时，再次触发全局快捷键创建一个新的浮窗。
- 新浮窗拥有独立的 AI 请求、回复内容和固定状态。
- 新浮窗不得复用、覆盖、清空或关闭已有固定结果。
- 多个固定结果可以同时存在，并可分别移动、缩放或取消固定。
- 未固定的新浮窗仍遵循普通浮窗的外部点击关闭规则。
- 暂不限制同时固定的结果浮窗数量。
- 新浮窗与已有窗口发生位置重叠时，应自动错开排列，并继续满足屏幕边界要求。

### 6.5 OpenRouter 余额迁移

#### 功能要求

1. 从浮窗中删除余额文字以及与浮窗生命周期绑定的余额刷新逻辑。
2. 在设置页“通用”标签内的“API 配置”区域展示 OpenRouter 账户信息。
3. 仅展示当前可用余额，不展示总充值额度和累计使用额度。
4. 展示余额最近一次成功刷新的时间。
5. 展示 OpenRouter 服务的当前连接状态，而不只是余额接口单次请求的状态。
6. 每次打开设置窗口时自动请求并刷新余额。
7. API 基础地址不是 OpenRouter 时，余额及其相关状态区域完全隐藏。
8. 余额请求不得阻塞设置窗口打开，也不得影响 API Key 和基础地址的编辑。
9. API Key 未配置、请求进行中、请求失败时，应提供对应的界面状态，不得将失败状态显示为有效余额。
10. 不提供手动刷新按钮。
11. 自动刷新失败时保留上一次成功获取的余额和刷新时间，并明确标记为旧数据，同时显示连接失败状态。
12. 余额固定保留小数点后两位。
13. 刷新时间使用相对时间展示，例如“刚刚”或“3 分钟前”。
14. 余额金额默认使用美元符号 `$`。
15. OpenRouter API Key 为空时，账户区域显示“请先配置 API Key”，且不发起账户请求。

#### 数据来源

现有实现通过 OpenRouter `/credits` 接口获取总额度和已使用额度，并以两者之差计算当前可用余额。本轮是否继续沿用该计算方式，需在实现阶段结合 OpenRouter 当前接口定义进行实时核验。

#### 连接与刷新规则

- 每次打开设置窗口时自动检查 OpenRouter 服务连接状态并刷新余额。
- 当前设置窗口保持打开期间不进行定时轮询。
- 不提供手动刷新入口。
- 自动刷新成功后更新余额、连接状态和刷新时间。
- 自动刷新失败时不把旧余额伪装成当前数据，必须同时显示“旧数据”标记和连接失败状态。

## 7. 状态与异常处理

### 7.1 Markdown

- 空回复：不显示 Markdown 内容区域。
- 普通纯文本：按普通文本正常展示。
- 未闭合的 Markdown：流式过程中按普通文本展示，闭合后更新为对应格式。
- 不受支持的 Markdown：降级展示可读文本，不得导致内容消失或应用崩溃。
- 流式更新频繁：不得明显阻塞窗口交互。
- 用户主动向上或向其他位置滚动：立即暂停自动滚动到底部，保持用户当前阅读位置。
- 用户重新滚动到底部：恢复对后续流式内容的自动跟随。

### 7.2 窗口缩放

- 用户拖拽至小于最小尺寸：限制在最小尺寸。
- 用户拖拽至大于允许上限：限制在五倍上限或屏幕允许尺寸，两者取更严格者。
- 显示器环境变化：重新校正保存尺寸，使窗口完整处于当前屏幕。
- 提示词列表页面：不允许通过鼠标拖拽缩放。

### 7.3 结果浮窗固定

- 点击固定图标：切换固定状态并立即更新图标视觉状态。
- 固定期间点击其他应用：结果浮窗继续显示。
- 固定期间移动或缩放：窗口保持在当前屏幕可用区域内。
- 固定期间 AI 继续输出：窗口不关闭，流式响应不中断。
- 取消固定：窗口不立即关闭；下一次点击窗口外部时按普通浮窗规则关闭。
- 固定期间再次触发 Y1Y：创建新的浮窗，已有固定结果保持不变。
- 多个固定窗口：分别维护固定状态、位置、尺寸和回复内容，任一窗口的操作不得误关闭其他固定窗口。
- 固定窗口关闭后：该窗口的固定状态被丢弃，不在后续浮窗或应用重启后恢复。

### 7.4 OpenRouter 余额

- API 地址不是 OpenRouter：整个余额区域隐藏。
- API Key 为空：不得发起余额请求，显示“请先配置 API Key”。
- 正在请求：显示加载状态。
- 请求成功：显示当前可用余额、刷新时间和成功连接状态。
- 请求失败且没有历史数据：显示连接失败状态，不伪造余额或刷新时间。
- 请求失败且存在历史数据：保留上一次成功余额和时间，同时明确标记为旧数据。
- 多次打开设置或快速修改配置：旧请求结果不得覆盖新配置对应的请求结果。

## 8. 非功能要求

1. 保持 macOS 原生界面风格，与现有 SwiftUI/AppKit 界面协调。
2. Markdown 流式渲染和窗口缩放不得明显影响输入、滚动和复制操作。
3. 不新增与本需求无关的外部数据收集或遥测。
4. API Key 继续使用现有安全存储方式，不在日志或错误提示中暴露完整密钥。
5. 尺寸持久化只保存窗口尺寸，不保存 AI 回复内容。
6. 固定窗口只需高于普通应用窗口，不得覆盖系统安全提示或突破 macOS 自身的窗口安全层级。

## 9. 明确不做

本轮不包含：

- Markdown 编辑
- Markdown 原文与渲染结果切换
- 导出 Markdown 或 PDF
- 图片生成、图片输入或图片上传
- 针对超长文档阅读的专项模式
- 浮窗位置持久化
- 固定状态持久化
- 新增独立关闭按钮或新的键盘关闭方式
- OpenRouter 以外 API 服务的余额查询
- API 请求层、模型选择系统或提示词系统的整体重构
- 与本轮四个目标无关的设置页重设计

## 11. 验收标准草案

1. AI 返回已确认范围内的 Markdown 时，浮窗能够在流式输出期间显示对应格式。
2. 流式内容包含暂未闭合或不支持的标记时，应用不崩溃，回复原始内容不丢失。
3. 未闭合的 Markdown 在流式过程中按普通文本展示，闭合后更新为相应格式。
4. 每个代码块均提供独立复制按钮。
5. 用户主动滚动离开底部后，新增流式内容不会改变其阅读位置；回到底部后恢复自动跟随。
6. 提示词列表页面保持固定紧凑尺寸，不能由用户拖拽缩放。
7. AI 回复页面能够通过鼠标拖拽缩放，且不能缩至 `380 × 360 pt` 以下。
8. AI 回复窗口宽度和高度分别不能超过最小值的五倍，也不能超出当前屏幕。
9. 用户调整后的 AI 回复窗口尺寸在关闭浮窗和重启应用后仍可恢复。
10. 进入 AI 回复页并开始生成结果前恢复已保存尺寸；返回提示词列表时恢复固定紧凑尺寸。
11. AI 回复页面右上角存在固定图标，固定后图标有明确的点亮状态。
12. 固定状态下，点击其他应用或浮窗外部不会关闭结果浮窗。
13. 固定状态下，结果浮窗保持在其他普通应用窗口上方。
14. 固定状态下可以移动和缩放结果浮窗，且窗口始终不超出当前屏幕。
15. 固定或取消固定不会中断流式回复或清空结果。
16. 取消固定后窗口不会立即关闭，下一次点击窗口外部时才关闭。
17. 已有固定结果时，再次触发全局快捷键会创建新浮窗，且已有结果不被替换或关闭。
18. 多个固定结果窗口能够独立移动、缩放和取消固定，互不影响。
19. 同时固定的窗口数量不受产品规则限制；新窗口发生重叠时自动错开。
20. 关闭固定结果后，其固定状态不会在下一次唤起或应用重启后恢复。
21. 浮窗位置不会跨浮窗关闭或应用重启保存。
22. 固定结果浮窗只要求高于普通应用窗口，不覆盖系统安全提示或更高层级系统窗口。
23. 浮窗中不再显示余额。
24. OpenRouter 配置下，每次打开设置窗口都会自动检查服务连接并异步刷新余额，不提供手动刷新。
25. 设置页能够区分余额加载中、连接成功和连接失败状态。
26. 刷新失败且有历史余额时，保留两位小数的余额和相对刷新时间，并明确标记为旧数据。
27. 非 OpenRouter API 地址下，余额区域完全不可见。
28. 余额金额使用美元符号 `$`。
29. OpenRouter API Key 为空时显示配置提醒，且不发起账户请求。
30. 界面中不存在“恢复默认窗口大小”入口。
