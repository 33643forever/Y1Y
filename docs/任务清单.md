# Y1Y OpenRouter 分支优化任务清单

## 1. 使用说明

- 依据文档：[需求说明.md](./需求说明.md)、[技术方案.md](./技术方案.md)
- 适用分支：`OpenRoter_build`
- 拆分原则：每个任务应能在一次对话、一个 commit 内完成并独立验收。
- 每个任务只处理清单中声明的范围，不顺带重构无关代码。
- 未实际运行的验证不得记录为“已通过”。
- 建议 commit 格式：`类型: 简短说明`，例如 `feat: add markdown block renderer`。

- `[ ]` 未开始
- `[~]` 进行中

## 5. 阶段三：流式 Markdown 与滚动

### T10 建立节流 Markdown 解析状态

- 状态：`[x]`
- 目标：避免每个流式字符都同步重建视图。
- 依赖：T08、T09
- 建议新增：`MarkdownRenderStore`
- 功能：
  - 接收持续变化的原始文本。
  - 在后台节流解析。
  - 回复结束时执行最终解析。
  - 取消旧解析任务，避免旧结果覆盖新文本。
- 不包含：
  - 不接入真实 AI 流。
- 验收：
  - 高频更新时解析次数少于文本更新次数。
  - 最终渲染结果对应最后一次完整文本。
  - 旧解析不会覆盖新结果。
- 验收记录（2026-07-30）：
  - 已新增 `MarkdownRenderStore`，默认以 `75 ms` 间隔节流，并在后台解析 Markdown。
  - 100 次连续文本更新实际只触发 1 次解析，最终快照为第 100 次文本。
  - 人为延迟旧解析后提交新文本，旧任务完成后仍未覆盖新结果。
  - 在节流等待期间调用结束方法会取消等待并立即解析最终全文，最终快照标记为完成态。
  - 检查输出为 `MarkdownRenderStore checks passed; 100 updates produced 1 parse`。
  - Xcode Debug 构建结果为 `BUILD SUCCEEDED`。
- 建议 commit：`feat: add throttled markdown render store`
